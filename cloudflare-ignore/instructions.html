BloodNet v2 (worker: bn2) - Deployment Guide

This file is for setup only. It is excluded from actual Cloudflare deployment via .cloudflareignore (all *.md files are excluded too, so README.md never gets deployed either).

1. Install Wrangler and log in

npm install -g wrangler
wrangler login

If you manage multiple Cloudflare accounts with named Wrangler profiles, activate one before proceeding:

wrangler auth activate <profile-name>

2. Create the D1 database

wrangler d1 create bnetv2_db

Copy the returned database_id into wrangler.toml under [[d1_databases]].

3. Apply the schema

wrangler d1 execute bnetv2_db --remote --file=./schema.sql

(Use --local instead of --remote while testing with wrangler dev.)

4. Create the KV namespace

wrangler kv namespace create BN2_KV

Copy the returned id into wrangler.toml under [[kv_namespaces]].

5. Set secrets

wrangler secret put ROOT_ADMIN_MOBILE
wrangler secret put ROOT_ADMIN_PASSWORD
wrangler secret put JWT_SECRET

ROOT_ADMIN_MOBILE is an 11-digit Bangladeshi mobile number (e.g. 01712345678) - this becomes the root admin's login identifier. JWT_SECRET should be a long random string, e.g. generate one with:

openssl rand -hex 32

6. Deploy

wrangler deploy

The worker is named bn2 in wrangler.toml. On first successful login with the root admin's mobile number, the root admin account is created automatically and will be forced to change its password immediately.

7. Configure the rest from the Admin Panel

Log in as the root admin and visit /admin/site-apis to add your ImgBB, DonorBD, and GreenSMS-compatible SMS gateway keys, and /admin/site-settings to set branding (logo, favicon, social preview, theme color, welcome text).

Test on local with remote data safely

wrangler d1 export bnetv2_db --remote --output=snapshot.sql
wrangler d1 execute bnetv2_db --local --file=./schema.sql
wrangler d1 execute bnetv2_db --local --file=./snapshot.sql

Takes snapshot from remote db to local and then injects it into a local D1 instance
